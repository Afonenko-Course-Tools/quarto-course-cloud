# Пример облачного задания

Пример показывает задание из двух шагов на двух виртуальных машинах: один шаг использует внешний файл проверки, второй — код внутри QMD. Нужны Quarto 1.10.18/1.11.5, CUE 0.17.1 и согласованное ядро курса. CI проверяет каналы Quarto `release` и `pre-release`.

Выполните из каталога этого примера:

```sh
quarto add ../../../quarto-course
quarto add ../..
quarto run render.ts student
quarto run render.ts full
```

Пример ожидает `quarto-course` рядом с репозиторием адаптера. При установке ядра из GitHub добавьте каталог владельца во все пути обработчиков Core и передайте `_extensions/Afonenko-Course-Tools/course-core` вторым аргументом `render.ts`, например `quarto run render.ts student _extensions/Afonenko-Course-Tools/course-core`. Команда `quarto add ../..` устанавливает адаптер из корня этого репозитория; её повторяют после изменения исходников.

При сборке проверяются разметка, связи, объявления машин и существование файлов. Команды из заданий не исполняются. Установленные расширения и результаты сборки исключены из Git; QMD и авторские ресурсы хранятся в репозитории.

`render.ts` создаёт отдельную свежую копию примера для каждого профиля, вызывает
установленный owner API Core, выполняет один native HTML render и проверяет
полученную модель до завершения owner. Команда выводит JSON с `stage`, путями
результатов и модели. HTML находится в каталоге этой попытки; он не копируется
обратно в исходный пример. После правки запускайте новую попытку.

Прямые `quarto render`/`quarto preview` не создают требуемую подготовку владельца
канонических `exr-*`. Используйте показанную команду и
[описание участвующего маршрута](../../README.md#текущий-авторский-маршрут-core).
Результат подтверждает разметку, модель и HTML; запуск виртуальных машин,
действий и экспорт для внешней платформы этот пример не выполняет.
