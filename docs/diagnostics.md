# Диагностика Cloud

Cloud проверяет авторское описание машин и действий. Локальные правила
проверяются до удаления закрытых блоков; после успешной native-команды явный
вызов установленного Core `entrypoints/check.ts . full` проверяет полную модель
и междокументные связи. Обычный render сохраняет факты текущих документов.
Сохранённый HTML или sidecar сам по себе не подтверждает успешное завершение
writer, поздних hooks или полной проверки модели.

Сообщение содержит исходный ID, русское пояснение, доступные `источник`,
`объект`, `поле`, связанные объекты и подсказку. Для упражнения связанными
объектами могут быть ключи шагов и имена VM. Общая обёртка CUE перечисляет
доступный контекст кандидата; точное нарушенное поле задаёт исходный вывод CUE,
а не предположение обёртки. Номер шага в пути CUE — индекс данных кандидата.
Обёртка не сопоставляет его со строкой QMD и не выполняет повторный обход
исходников ради координат. Временный `candidate.json` и Lua-файлы в traceback
не являются строками входного QMD.

| ID | Смысл и контекст | Исправление |
| --- | --- | --- |
| `CLOUD001_check` | В шаге отсутствует действие `check`; CUE указывает шаг. | Добавьте проверку для шага. |
| `CLOUD002_uniqueActions` | Пара `(vm, phase)` повторяется внутри шага. | Оставьте одно действие для каждой пары. |
| `CLOUD003_checkPerVm` | У участвующей в шаге машины нет действия `check`. | Добавьте проверку для каждой машины этого шага. |
| `CLOUD004_uniqueSteps` | Ключи шагов упражнения повторяются. | Задайте каждому шагу уникальный `key`. |
| `CLOUD005_declaredVm` | Машина действия не объявлена в работе, включающей упражнение. Локальная проверка даёт упражнение, шаг, VM и ID работы; междокументная проверка CUE сохраняет путь `работа/упражнение/шаг/VM`. | Объявите машину в `cloud.virtual-machines` на странице работы или исправьте `vm`. |
| `CLOUD006_prepareVm` | Действие `prepare` ссылается на необъявленную машину. | Исправьте имя VM или объявите её на странице работы. |
| `CLOUD007_uniquePrepare` | Для машины задано несколько действий `prepare`. | Оставьте одно действие подготовки на машину. |
| `CLOUD.ACTION_SOURCE_INVALID` | Путь `source.file` имеет неподдерживаемую форму, разрешается за пределы корня курса или указывает на объект, который не является файлом. Доступны входной документ, упражнение/работа, шаг, VM и путь. | Укажите файл от корня курса с одним начальным `/`; проверьте цель символической ссылки. |
| `CORE.ADAPTER_INVALID` | Core не находит ровно один установленный пакет явно включённого адаптера. | Проверьте установку Cloud и список `course.adapters`. [Правила Core](https://github.com/Afonenko-Course-Tools/quarto-course/blob/v3.0.0/README.md). |

CUE также отклоняет пустые/неверные обязательные поля (`key`, `phase`, `vm`,
язык, источник), неизвестные атрибуты/классы, действия до первого шага и неверное
размещение маркеров. Для этих полей не создаются псевдонимы ID: остаётся исходный
путь и отказ CUE. Язык, фазы, VM, API и имена полей не переводятся.

## Внешние отказы

`ExternalToolFailure` обозначает внешний отказ проверки: CUE мог отклонить
кандидат либо не запуститься. Русское пояснение добавляет доступный контекст;
исходный CUE ID, tool, код завершения, stdout/stderr остаются в выводе.
Обёртка не извлекает semantic ID из stderr и не заменяет исходную причину.
Недоступный или отсутствующий файл приводит к `ExternalToolFailure` с исходной
IO-причиной (`NotFound`, права доступа и т. п.). Это не доказательство нарушения
учебного правила и не новый CUE ID. Если путь доступен, но указывает на каталог,
срабатывает существующий guard с `CLOUD.ACTION_SOURCE_INVALID`.

В TS-проверке путей собственные ошибки имеют имя `ExtensionDiagnostic` и `code`;
внешние — имя `ExternalToolFailure` и `cause`. Это локальные Error-объекты,
которые не сериализуются в модель или новый общий отчёт. Неизвестные исключения
сохраняют stack; их не следует объяснять как ошибку автора без исходной причины.
Lua guard добавляет контекст к исходному внешнему отказу в обычном сообщении;
структурированный Error-объект в Lua не вводится.

## Что подтверждает демонстрация

[Пример](../examples/course/README.md) собирает русскую веб-книгу и проверяет
выбранный экспорт полной исходной лабораторной. Файл `BUILD.json` содержит
сведения о сборке и `livePlatformVerified: false`. Наличие действий в HTML,
успешные CUE-проверки и выбранный экспорт не подтверждают создание VM,
выполнение shell-команд или обмен с облачной инфраструктурой.

Контрпримеры находятся только во внутренних тестах (`tests/check.ts` и
`tests/native-model.ts`), а не среди готовых учебных страниц. Таблица, Lua/TS
обёртки и отрицательные тесты проверяются вместе; отдельного генератора реестра
диагностики нет.
