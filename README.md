# Облачные задания курса

Расширение `course-cloud` описывает виртуальные машины, шаги работы и проверку облачных заданий в Quarto. Оно дополняет текущую спецификацию ядра курса: ядро собирает общую модель курса, а адаптер добавляет раздел `extensions.cloud` и проверяет его правилами CUE.

Ядро, адаптер и конфигурация курса обновляются совместно. В YAML не указывают версию схемы; старые формы описания не поддерживаются. Номер в `_extension.yml` служит метаданными устанавливаемого пакета.

## Подключение

Нужны актуальные Quarto и CUE. CI проверяет каналы Quarto `release` и `pre-release`. Python, Node.js и отдельная установка Deno не требуются. Рабочий путь должен быть без пробелов из-за разбора команд сборки в Quarto; кириллица допустима.

```sh
quarto add Afonenko-Course-Tools/quarto-course
quarto add Afonenko-Course-Tools/quarto-course-cloud
```

В `_quarto.yml`:

```yaml
project:
  pre-render: _extensions/Afonenko-Course-Tools/course-core/entrypoints/pre.ts
  post-render: _extensions/Afonenko-Course-Tools/course-core/entrypoints/post.ts
course:
  id: cloud-course
  validate: true
  adapters: [cloud]
filters: [course-core, course-cloud]
```

Ядро должно предшествовать адаптеру в списке фильтров. `course.adapters` явно включает контракт; установка пакета сама по себе его не активирует. Пути к обработчикам указывают установленный каталог ядра; при локальной установке это `_extensions/course-core/`. Установленный пакет определяется по `contract.json`, в котором заданы имя адаптера и путь к его правилам.

## Описание задания

````qmd
:::: {#exr-service target="cloud"}
## Состояние службы

### Настройка {.cloud-step key="configure"}

Создайте файл состояния со строкой `ready`.

```{.sh .cloud-action phase="check" vm="host" file="/projects/service/check.sh"}
```
::::
````

Задание — блок с идентификатором `exr-…` и `target="cloud"`. Его первый элемент — заголовок. Заголовок с классом `.cloud-step` начинает шаг; `key` задаёт уникальный в пределах задания ключ. Обычные подзаголовки шагов не создают.

Действие задаётся блоком кода с языком, классом `.cloud-action`, фазой `phase` и именем машины `vm`. Код записывают в самом блоке либо в файле, путь к которому указывает `file` от корня проекта Quarto. Должен быть выбран ровно один источник.

| Фаза | Назначение |
|---|---|
| `check` | Проверка выполненной работы; обязательна для каждой машины, участвующей в шаге. |
| `solution` | Авторское решение. |
| `pre-step` | Подготовка перед шагом. |
| `post-step` | Действия после шага. |

Внутри шага пара `(vm, phase)` уникальна. Заголовки шагов и блоки действий располагают непосредственно в блоке задания. Проверка отклоняет неизвестные атрибуты, неподдерживаемые классы, действия до первого шага и неверную вложенность.

## Машины и подготовка занятия

Машины объявляют в метаданных страницы занятия:

```yaml
assessment:
  kind: lab
cloud:
  virtual-machines:
    host:
      template: ubuntu-host
```

Значение `template` — имя шаблона виртуальной машины. Каждая машина, используемая заданиями занятия, должна быть объявлена на этой странице. Состав занятия определяется ссылками в `.assessment-items` по общим правилам ядра курса.

Действие `phase="prepare"` размещают непосредственно на странице занятия. Оно относится ко всему занятию; для каждой объявленной машины допустимо одно такое действие. Однократный запуск обеспечивает среда исполнения.

При сборке код действий отображается как часть документа и проходит структурную проверку. Сборка не запускает команды и виртуальные машины. Авторское решение, которое не должно быть доступно студентам, следует включать только в закрытое представление курса по правилам ядра курса.

## Пример и проверка

```sh
cd examples/course
quarto add ../../../quarto-course
quarto add ../..
quarto render
quarto preview
```

Пример содержит две виртуальные машины, два шага и внешний файл проверки `check.sh`. Пример ожидает соседний локальный репозиторий `quarto-course`; при установке ядра из GitHub укажите в `_quarto.yml` путь с каталогом владельца. После изменения адаптера повторите `quarto add ../..`, чтобы обновить его установленную копию.

Из корня репозитория запускается интеграционная проверка:

```sh
quarto run tests/check.ts ../quarto-course
```

Она устанавливает оба расширения во временный проект, собирает книгу и проверяет модель CUE. Отдельно проверяются ошибки: отсутствие `check`, повтор ключа шага, необъявленная машина и отсутствующий файл. После неуспешной сборки предыдущая модель должна быть удалена. Временные данные удаляются автоматически.

GitHub Actions выполняет эти проверки для PR, изменений в основной ветке, по запросу и еженедельно в каналах Quarto `release` и `pre-release`. Используется актуальный стабильный CUE. CI получает согласованный коммит `Afonenko-Course-Tools/quarto-course`: коммит обновляется вместе с адаптером, выбор версии схемы в курсе не вводится.

## Границы расширения и хранение исходников

Правила находятся в `_extensions/course-cloud/spec/cloud.cue`. Адаптер извлекает данные и проверяет авторское описание. Экспорт `_produced.yaml`, запуск машин, настройка сетей и дисков и планирование работы относятся к компилятору и среде исполнения; в этом расширении они не реализованы.

В Git хранятся исходники расширения, правила CUE, QMD и авторские ресурсы. Установленные зависимости в `examples/**/_extensions/` и результаты сборки исключены через `.gitignore`. Адрес GitHub используется только при установке: сборка не привязана к владельцу репозитория или имени рабочего каталога.

## Единый словарь и архитектура

`contract.json` — источник идентификатора адаптера и повторно используемых
допустимых значений. Lua читает этот файл непосредственно; объявления
перечислений в CUE создаёт `quarto run tools/sync-contract.ts`. Проверка
`quarto run tools/sync-contract.ts --check` обнаруживает рассогласование и
выполняется в CI. Остальные ограничения модели задаются только в CUE.
Генератор словаря нужен сопровождающему расширения; автор курса получает
готовые файлы и не запускает его.

Модули извлечения не выполняют команды задания и не создают файлов целевой
платформы. Фильтр отвечает за обход документа и запись фрагмента, отдельные
модули — за преобразование разметки, схема CUE — за ограничения модели.
